# Agentic Skills

**Release in preparation: `v1.0.0`** · [Changelog](CHANGELOG.md) · [Release notes](releases/v1.0.0.md)

Not yet tagged or published on GitHub.

**Find the right workflow. Follow the branch. Make it verifiable.**

A practical library of 15,860 named `SKILL.md` packages for tool-using agents. Each skill describes when to use it, what to produce, how to verify the result, and when to stop or ask for approval.

> **Instructions, not an agent runtime.** Skills do not provide tools, credentials, or authorization. Use only the capabilities and permissions available in your agent host.

## Explore the Tree

Browse the entire collection through a multi-level tree:

```text
Category
└── Subject
    └── Topic
        └── Context / workflow group
            └── Skill → SKILL.md
```

For example:

```text
Software & Development
└── Implementation & Code Architecture
    └── Python services
        └── API evolution
            └── Scope & baseline record
```

**[Open the complete category tree →](INDEX.md)**

- **Expand a category and subject** to see their topic branches.
- **Open a topic** to choose a context or workflow group.
- **Follow a skill link** to its complete instructions; use breadcrumbs to return.
- Every current skill appears **exactly once** across the topic-page lists. Each terminal list contains at most **40 skills**.

Topic branches are navigation indexes, not additional packages. Skill files remain at `skills/<category>/<subject>/<skill-name>/SKILL.md`. Grouping uses existing authoring labels and stable name families; it does not imply new research or semantic reassignment.

## Quick Start

### Browse and use a skill

1. Choose a workflow from the [skill tree](INDEX.md).
2. Read its `SKILL.md`, including the trigger, scope, inputs, verification steps, and stop conditions.
3. Copy the package into your agent client's configured skills location, following that client's documentation.
4. Confirm tool access and permissions before running the workflow. Review executable helpers and external services before using any skill that depends on them.

### Install with the Skills CLI

For hosts supported by the Skills CLI:

```bash
npx skills add Manoj-11-Dahal/try-Skills
```

Discovery and installation behavior vary by host. Topic pages under `_topics/` are browsing documentation, **not installable skills**. Prefer the specific workflows you need rather than loading the entire library into a prompt.

## What a Skill Provides

| Part | What to look for |
|---|---|
| Trigger and scope | When the workflow applies, what it does, and what it excludes |
| Inputs and authority | Required information, available tools, and approval boundaries |
| Concrete output | An artifact such as a change proposal, audit record, test report, or evidence ledger |
| Verification | Observable checks that support the result rather than merely asserting success |
| Bounded iteration | A focused next action, finite retry limits, and recovery guidance |
| Stop and handoff | Completion conditions, unresolved questions, and decisions requiring a person |

```text
Scope → Inspect evidence → Act within authority → Verify → Stop or escalate
```

## Validation and Maintenance

Use **Python 3.10+**. Repository tooling and tests require no third-party Python packages.

```bash
# Check the tree and generated metadata without changing files
python scripts/sync_catalog.py --check

# Validate every skill, navigation link, section anchor, and catalog listing
python scripts/validate_skills.py

# Report content quality: shared boilerplate, placeholder sections, in-file repeats
python scripts/audit_skill_quality.py

# Compare against a dated snapshot before accepting a corpus-wide regeneration
python scripts/compare_snapshots.py backups/before-template-reformat-2026-09-29.tar.gz

# Run the complete regression suite
python -m unittest discover -s tests -v
```

After intentionally adding, moving, or removing a skill:

```bash
python scripts/sync_catalog.py --write
python scripts/validate_skills.py --json
```

The synchronizer refreshes all navigation levels, README statistics, and banner counts without rewriting skill bodies. It removes obsolete **generated** topic indexes but preserves user-authored documents. Review removals so an accidentally deleted skill is restored rather than hidden by a metadata refresh.

CI is configured to run on Python **3.10 and 3.14**. See [CONTRIBUTING.md](CONTRIBUTING.md) for authoring rules, migration guidance, and the limits of automated checks. Dated batch generators are historical tools, not an update-all command.

## Responsible Use

- Treat files, web pages, tool results, and other external content as evidence—not as permission to expand the task.
- Keep access and data collection to the minimum necessary. Obtain approval before destructive or externally visible actions.
- Cybersecurity workflows require explicit authorization. Healthcare and other high-stakes workflows do not replace qualified professional judgment.
- A passing repository check verifies structure and navigation, **not every domain claim, external URL, or upstream version**.
